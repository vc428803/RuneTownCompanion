# RuneTown Companion

RuneTown Companion 是一個使用 **Java 21** 開發的領域模型原型，目前定位為 **Nexelyth 的人生進程系統（Life Progression）原型**。

> **你不是因為反覆刷取而成長，  
> 而是因為真正生活過而成長。**

---

## 專案方向

Nexelyth 不希望把現實人生做成：

```text
工作 / 讀書 / 運動
        ↓
      經驗值
        ↓
       升級
```

而是：

```text
真實人生事件
      ↓
有意義的成長證據
      ↓
      收藏
      ↓
  路徑 / 身份
      ↓
   角色成長
```

核心原則：

> **成長來自證據，而不是刷取。**

---

## 人生進程 vs 戰鬥進程

```text
                    Nexelyth
                       │
          ┌────────────┴────────────┐
          │                         │
       人生進程                  戰鬥進程
          │                         │
       現實人生                  VR 世界
          │                         │
   你正在成為誰                你如何戰鬥
```

### 人生進程

可能來自：

- 學習
- 工作
- 創作
- 服務
- 探索
- 成就

### 戰鬥進程

未來可能包含：

- 武器
- 武器熟練度
- 技能
- 裝備
- 流派配置
- 戰鬥屬性

兩者不共用同一套經驗值 / 等級系統。

---

## 核心領域方向

目前主要探索：

```text
一般活動
   ↓
有意義事件
   ↓
成長證據
   ↓
收藏
```

不是所有活動都等於成長證據。

目前最重要的領域問題：

> **什麼樣的現實事件，才值得成為一筆收藏？**

---

## 跨職業設計

系統不能只適用於軟體工程師。

未來應能適用老師、廚師、設計師、護理師、學生、工程師等不同背景。

目前暫定探索的成長路徑：

```text
知識
技藝
創造
服務
探索
精熟
```

這些目前只是領域假設，尚未固定。

例如：

```text
完成企業軟體系統
→ 技藝 / 創造 / 精熟

完成一套教材
→ 知識 / 創造 / 服務
```

## 目前狀態

目前已完成：

- Java 21
- Maven
- JUnit 5
- Git / GitHub
- 基本 Java 領域模型
- 單元測試環境

目前 Repository 仍有早期：

```text
Player
→ EXP
→ Level Up
```

這屬於前一階段 Java / JUnit 練習，**不代表目前 Nexelyth 的人生進程方向**。

---

## 目前優先目標

目前第一優先：

> **建立最小可用的人生收藏 / 成長證據原型。**

近期開發方向：

```text
定義成長證據
      ↓
定義收藏
      ↓
建立最小領域模型
      ↓
單元測試
      ↓
重構
```

初步可能的模型：

```text
CollectionItem

- id
- title
- description
- category
- acquiredAt
- evidenceType
```

但這不是最終資料結構。

---

## 尚未定案的問題

1. 什麼條件讓一件事件值得成為成長證據？
2. 一筆收藏是否可以對應多個成長路徑？
3. 路徑由玩家、規則、AI 還是混合方式判斷？
4. 成長證據是否需要驗證？
5. 收藏只是紀錄，還是身份的一部分？
